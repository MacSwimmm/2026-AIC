# 2.1.1 验证记录

电脑连接时，MaixCAM Pro 停止缩放、叠加和显示相机图像，只保留操作界面。界面在触摸、保存数据或操作状态变化时重绘，空闲时不持续重绘；触摸每个处理循环仍读取。最后一个连续图像订阅断开后自动恢复本机预览，连接期间的标定/图像选点在电脑端完成。

640 × 480 图像、YOLO 模型与阈值、地面换算和设备端数据保存方式保留。本轮不重新测量实际场地误差。

## 本轮实测与计数

实机 MaixCAM Pro，经 USB 网络连接电脑。本轮同一场景、每模式约 20 秒的连续 JPEG 接收并解码结果：

| 版本 | 普通模式 | YOLO11 |
|---|---:|---:|
| 修改前 2.1.0，本机约 1 fps 预览 | 29.11 fps | 24.18 fps |
| 修改后 2.1.1，本机仅操作界面 | 29.75 fps | 24.97 fps |

前后报告分别为 `performance-controls-before.json` 与 `performance-pc.json`，各自包含所测设备源文件哈希。本轮约提高 2.2% / 3.3%，不将场景变化或浏览器负载变化都归因于本机预览。新版本观察窗口内本机预览新增帧数为 0；只在切入按钮模式时重绘一次屏幕。

带标定、网格和目标点的复测见 `performance-calibrated-pc.json`；真实浏览器解码/绘制见 `pc-workflow-validation.json`。具体采样窗口以 JSON 为准。目标数量、光照、图片复杂度、网络和温度会影响结果。

带标定/目标的连续接收为普通 29.93 fps、YOLO 24.90 fps；Edge 实际解码并绘制为普通 25.58 fps、YOLO 20.79 fps。两项来自不同负载窗口，分别计数。

电脑界面分别显示：

- **实际处理 FPS**：设备完成处理的新帧计数速率。
- **电脑显示 FPS**：浏览器实际成功解码并绘制的不同帧，按近两秒采样；冻结显示「已冻结」，过期采样自动消退。

连续 JPEG 接收、浏览器绘制与本机屏幕刷新独立计数，不混用。电脑帧龄是接收有效期指标，不是相机到屏幕的端到端延迟。

**本次未配置 Wi-Fi，以上不是无线吞吐实测。** 后续连接同一手机热点后，在电脑填写相机「电脑连接」页显示的 Wi-Fi IP，使用同一套取图及数据接口。

## 软件与实机操作

`python -m unittest discover -s tests -q`：**58 项通过**，见 `unit-validation.json`。覆盖原有几何、数据持久化、网络与帧有效期、进程生命周期、JPEG/识别结果配对，并增加：电脑连接时不访问相机预览像素、禁止在空白区域选点、断开后恢复预览、操作界面仅在状态变化时需要重绘。

| 本轮报告/工具 | 验证范围 |
|---|---|
| `native-validation.json` / `check_native.py --performance` | 真实屏幕与注入触屏事件完成尺寸输入、四点标定、选点保存、文件/API 一致；重启、菜单退出/再启动保持数据；识别菜单双向切换 |
| `pc-workflow-validation.json` / `check_pc_workflow.py` | 本版 EXE + Edge + 真实相机，网页标定、选点、校验、保存/删除/导出、四模式、帧率双读数与冻结、重连保持标定 |
| `controls-validation.json` / `check_controls.py` | 电脑连接时本机预览计数不前进、空闲屏幕不重绘而相机继续前进；触摸模式菜单可用；断开恢复预览，重连再次关闭预览，数据与模式保持 |
| `stability-validation.json` / `check_stability.py --duration 120` | 本版 EXE 连接并保持 YOLO 的连续状态采样与 JPEG 解码观察；具体时长、错误数和产物哈希见报告 |

本轮连续 YOLO 观察 120.20 秒通过：600 次状态采样、120 张抽样 JPEG，断线采样 0、请求/解码错误 0，标定与模式保持。结束后恢复普通模式；每秒抽样 JPEG 的频率不作为视频帧率。

本机与网页标定检查只在无正式标定/目标时创建合成数据，并清理自身数据；已有正式数据时拒绝覆盖。合成坐标和注入触屏事件不代替实际场地误差或手指触摸体验验收。模式运行通过也不代表真实物体或 AprilTag 的检测精度已验收。

## 交付一致性

交付 `MaixGround-2.1.1.zip` 与 `MaixVisionConsole.exe`。`python tools/verify_package.py` 验证 EXE 内网页、设备源文件、几何文件及电脑编译代码与源码一致；`release-manifest.json` 记录文件大小、SHA-256 和源文件哈希。安装包文件哈希见 `native-package.json`，本机与按钮模式验证记录引用对应的安装包哈希。

现场照片、凭据、标定、目标点和设备运行库不提交公开仓库。截图只保留本地 `data/qa/`。

## 保留的历史依据

`performance-standalone.json`、`live-validation.json`、`live-browser-validation.json`、`yolo-regression-validation.json` 为 2.1.0 历史报告，其中十轮开关、三次推理中重连及 600 秒连续 YOLO 不作为 2.1.1 的重新实测。`browser-validation.json` 是旧版模拟画面/响应式布局检查；`pi-delivery-validation.json` 是 2.0.0 设备到电脑接收示例的历史通信检查。本版保留树莓派接口并通过协议单元回归，真实树莓派联调留待后续。

`nn-pairing-validation.json` 是 2.1.0 在实机以 120 次随机交替的空白/已知物体输入及随机调用间隔，与同步推理比对双缓冲上一输入结果配对规律的记录。本版没有改动推理或图像配对实现，单元回归仍覆盖对应图像和采集时间保留；该记录不代表现场识别准确率评测。

当前仍先加载模型再打开相机，进入/退出 YOLO 时完整重启取图进程，相机、NN、JPEG、显示保留在主线程。部署/安装前释放系统菜单的相机资源，避免同时运行两个相机应用。Linux 单次 `D` 状态只表示驱动等待，结合帧前进和有界退出判断。

本次改动集中于视觉项目与仓库首页。ControlDesk 模板来源见 `TEMPLATE.md`。
