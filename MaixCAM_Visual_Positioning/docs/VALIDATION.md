# 2.1.0 验证记录

本版优先提高实际处理与电脑取图速率，保留 640 × 480 标定图像、原 YOLO 模型和阈值、地面换算算法及设备端持久化数据。电脑连接时降低本机屏幕刷新；标定保留冻结预览，本机预览按屏幕比例缩放，触摸在每次处理循环读取。

## 实际帧率

实机 MaixCAM Pro，经 USB 网络连接电脑。计数使用不同帧的 `(session_id, seq)`；浏览器另计实际解码并绘制的图片，不把界面数字或重复图片算作新帧。

| 测量场景 | 普通模式 | YOLO11 |
|---|---:|---:|
| 本机独立运行，实际处理 | 29.30 fps | 27.21 fps |
| 电脑连续接收并实际解码新 JPEG | 29.11 fps | 22.64 fps |
| 已标定并保存目标点，电脑连续接收并解码 | 29.12 fps | 22.43 fps |
| Windows EXE + Edge，网页实际解码并绘制 | 24.93 fps | 16.97 fps |

处理/连续取图为每模式约 15～20 秒采样，浏览器为每模式约 5 秒采样，具体窗口和间隔见 `performance-standalone.json`、`performance-pc.json`、`performance-calibrated-pc.json`、`pc-workflow-validation.json`。这不是所有光照、目标数量、网络和温度下的性能保证。

**本次未配置 Wi-Fi，以上不作为无线吞吐实测。** 用户后续连接同一手机热点后，在电脑填写相机「电脑连接」页显示的 Wi-Fi IP，使用相同的取图与数据接口。

## 软件与图像配对检查

`python -m unittest discover -s tests -q`：**56 项通过**，见 `unit-validation.json`。覆盖原有几何、镜头、输入边界、HTTP 来源、帧有效期、退出与进程交接、数据原子保存，以及连续图像解析、YOLO 延后帧配对和不依赖重绘的触屏模式选择。

YOLO 双缓冲会返回上一输入的结果。本版保留对应的完整 RGB 图像及采集时间，随后编码与这些结果配对的图像。实机使用 120 次随机交替的空白/已知物体输入及随机调用间隔，与同步推理基准比对，无配对差异；见 `nn-pairing-validation.json`。这项检查验证输入/结果的配对规律，不代表现场识别准确率评测。

## 本机与电脑操作

`python tools/check_native.py --performance` 在真实相机、显示屏和 MaixPy 上注入 Linux 触屏事件，见 `native-validation.json`：

- 输入场地尺寸、冻结画面、选择四角并保存标定。
- 点击取坐标、保存目标；设备文件与 API 导出一致。
- 应用重启、退出后从系统菜单重新启动，标定及目标批次保留。
- 退出恢复一份原厂界面；明确的识别模式菜单可进入和退出 YOLO。
- 检查只创建并清理自身合成标定；已有正式数据时工具拒绝覆盖。

`python tools/check_pc_workflow.py` 使用本版独立 EXE、真实 USB 相机与 Edge 浏览器，见 `pc-workflow-validation.json`：

- 网页完成四点标定、选点、保存、独立校验和目标删除，设备导出与网页操作一致。
- 四种识别模式都可选择；断开再连接保留设备标定。
- 只清理本次合成数据；浏览器脚本异常 0。

`live-browser-validation.json` 另覆盖三轮网页连接/断开、冻结/解冻与模式切换；电脑断开后设备应用继续运行。`live-validation.json` 覆盖普通、YOLO11、红色标记及 AprilTag 的 640 × 480 JPEG 解码和帧序号前进。采样现场未检出目标，不能把这些流程通过当作实际物体/标签的识别精度通过。

合成坐标和注入触摸事件不代替实际场地误差或手指触摸体验验收。几何与模型参数保留，但本轮没有重新测量现场定位误差。

## YOLO 重连与连续运行

`python tools/check_yolo_regression.py` 验证十轮进入/退出 YOLO、三次推理中重连、立即断开再连接，以及保持 YOLO 模式的 600 秒连续观察。完整结果见 `yolo-regression-validation.json` 与 `stability-validation.json`；以报告中的 `passed`、模式、实际观察时长及产物 SHA-256 为准。

本次全部通过：连续观察 600.17 秒，2,996 次状态采样、600 张抽样 JPEG 解码，断线采样 0、请求/解码错误 0；最大状态响应时间 0.0275 秒、最大采样帧龄 0.0896 秒。标定保持，检查结束恢复普通模式。

连续观察检查状态可达、JPEG 实际解码、标定保持和识别模式保持；每秒抽取一张 JPEG，不将其抽样频率当作视频帧率。帧率使用前述独立连续取图检查。电脑帧龄是接收有效期指标，不是相机到屏幕的端到端延迟。

## 交付一致性

交付 `MaixGround-2.1.0.zip` 与 `MaixVisionConsole.exe`。`python tools/verify_package.py` 验证 EXE 内网页、设备源文件、几何文件及电脑编译代码与源码一致；`release-manifest.json` 记录文件大小、SHA-256 和源文件哈希。安装包文件哈希见 `native-package.json`，与本机验证记录中的包哈希对应。

旧版 `browser-validation.json`（模拟画面/响应式布局）与 `pi-delivery-validation.json`（2.0.0 设备到电脑接收示例）保留为历史资料，**不作为 2.1.0 的实机验收**。树莓派协议单元检查仍保留；实际树莓派配网和导航集成按用户要求留待后续。

## 保留的运行库约束

1.0.2 基线为 `d003212e3c90d4bc74a3a8b2e4d018b7c3a8910e`，此前的相机/模型本地库崩溃经原厂工具重装官方 1.22.0 运行库恢复；这不是正常升级步骤。当前仍先加载模型再打开相机，进入/退出 YOLO 时完整重启取图进程，避免同进程相机/模型资源交接故障。

本版保持相机、NN、JPEG 和显示在主线程操作。单次 Linux `D` 状态只表示驱动等待；检查结合帧前进和有界进程退出判断，不将其单独当作卡死。

本次提交集中于视觉项目与仓库首页，电机工程不参与改动。ControlDesk 模板来源见 `TEMPLATE.md`。现场照片、凭据、标定、目标点及设备运行库不提交公开仓库。
